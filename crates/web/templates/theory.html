Theory — Real MLP vs Complex-Valued MLP

This project learns the inverse map from waveguide scattering parameters S11, S21 to the complex permittivity ε = ε′ − jε″. Two architectures are benchmarked: a standard Real MLP that treats the four real scalars independently, and a Complex-Valued MLP (CVNN) that carries the native complex structure of S-parameters through the whole forward pass.

The problem — and why we replace NRW

A sample of the Material Under Test (MUT) of thickness d is placed inside a rectangular waveguide of width a and excited at frequency f. A Vector Network Analyser records the complex reflection and transmission coefficients S11 (reflected wave at port 1) and S21 (wave transmitted to port 2). The inversion task is: recover the complex permittivity ε = ε′ − jε″ of the MUT from the measured (S11, S21).

The Nicolson–Ross–Weir (NRW) algorithm solves this analytically: it derives a reflection coefficient Γ and a transmission factor T from (S11, S21), picks the physically meaningful root of a complex logarithm, and algebraically inverts to ε. It is closed-form but brittle: multiple branches of the logarithm must be selected by hand, and at half-wavelength-multiple thicknesses the matrix is ill-conditioned. This project replaces that pipeline with a neural network that maps (S₁₁, S₂₁) → (ε′, ε″) in one shot.

  • NRW strengths: closed-form, no training, fast single-shot evaluation.
  • NRW weaknesses: branch ambiguity of the complex log, ill-conditioning near d ≈ k·λg/2, noise amplification for low-loss materials.
  • NN replacement: a single feed-forward pass, no branch selection, smooth behaviour across the whole (ε′, ε″) grid. The training data is generated by running the forward NRW model on a sweep of permittivities — so the network learns the inverse map without any hand-picked branch rules.

Real Real-Valued MLP   ℝ4 → ℝH → ℝ2

A plain feed-forward regressor. The four real components of the S-parameters are stacked into a single real vector of length 4, passed through one hidden layer of H neurons with a pointwise non-linearity σ, and projected to 2 real outputs interpreted as (ε′, ε″).

real neuron (scalar activation) real weight (single scalar)
forward pass (real, per sample x ∈ ℝ⁴): h = σ( N( W₁·x + b₁ ) ) W₁ ∈ ℝ^(H×4), b₁ ∈ ℝ^H y = W₂·h + b₂ W₂ ∈ ℝ^(2×H), b₂ ∈ ℝ² parameter count: base : 7H + 2 + LayerNorm/BatchNorm: +2H ⇒ 9H + 2 (default with norm)

Activations searchable by HPO: relu, tanh, gelu, leaky_relu, elu — all stateless. Regularisation: dropout p ∈ [0, 0.4], input noise, optional LayerNorm / BatchNorm. Simple and fast; ignores the algebraic pairing between real and imaginary halves of each S-parameter.

Complex Complex-Valued MLP (CVNN)   ℂ² → ℂ^H → ℂ¹

Treats each S-parameter as a single complex number rather than two unrelated reals. Weights, biases and activations are all complex-valued. The input is a 2-vector of complexes [S₁₁, S₂₁], the hidden layer has H complex neurons, and the output is a single complex number reinterpreted as ε = ε′ − jε″.

Complex activations σℂ — eight variants, all searchable by HPO. Phase-preserving forms (cardioid, cgelu, hybrid_cardioid_gelu, worelu) dominate the Pareto front; the rest stay in the menu in case the preferred ranking shifts as the dataset / loss change.

Always-on architectural pieces

Per-half LayerNorm between ComplexLinear and the activation (independent γ, β on Re and Im — 4·H scalars). Softplus output clamp at every forward pass (training + inference) pins ε̂′ ≥ 1 and Im(ε̂) ≤ 0 in the physical regime. Stable-sqrt NRW path bounds the backward gradient at the vacuum boundary ε ≈ 1+0j where the principal sqrt has a 1/√0 pole; always on for the physics-forward loss.

At inference the 4 real measurements (S₁₁.r, S₁₁.i, S₂₁.r, S₂₁.i) are repacked into a 2-vector of complexes before the forward pass; the network never sees them as independent reals.

Stage stack — five interventions that close the worst-case tail

The HPO winner alone (single model, no overlay, no ensemble, no refinement) leaves both pipelines with a long-tail problem: worst-case relative error on a single test sample spikes to ≈50 % (Complex) or ≈138 % (Real) on the hard grid. Stacking five interventions on top of the HPO recipe closes that tail to under 10 % on every one of 7 test seeds for both families. Stages 1–4 are training-time only; Stage 5 is opt-in at inference.

Stage Intervention What it solves Worst max-err / OK@1
0 HPO recipe verbatim, single model Baseline ≈50 % / ≈95 %
1 Train-overlay-only 8×8 patch in [1, 2.5] × [0, 1.75] HPO sampled the singular corner sparsely. Adding 64 anchor points only at training time (eval grid stays standard) teaches the model the local geometry. ≈45 % / ≈94 %
2 EpsRelMse loss override (replaces smooth_l1) Variance crusher. Bulk samples (|ε| ≈ 30) dominate vanilla MSE and the singular corner (|ε| ≈ 1.5) vanishes in the gradient. Dividing by |ε| rebalances; the optimiser literally minimises the reported metric. ≈11 % / ≈88 %
3 Activation override: worelu for Complex, relu for Real HPO's activation pick was optimal on the easy home grid, not on hard. ReLU's hard-zero gradient breaks correlated worst-sample errors that LeakyReLU's smoother slope produced across ensemble members. ≈11 % / ≈83 % (bimodal — 2/7 seeds stuck)
4 Median ensemble: 3 (Complex) / 5 (Real) models on adjacent seeds, per-element median Median (not mean) discards a single bad-seed prediction sample-by-sample. Real needs 5 because LeakyReLU/ReLU members otherwise miss the same singular-corner sample together. 5.7 % / 91.3–95.8 % (training-only feasibility, 7/7)
5 NRW refinement (opt-in, at inference): 100 Adam steps on |NRW(ε̂) − S|², warm-started at the median prediction Levenberg–Marquardt-style polish. The MLP picks the right basin; the physics solver finds the exact bottom. Per-sample optimisation pass — opt-in only. 3.16 % (Complex) / 4.56 % (Real)

Median, not mean. If two healthy seeds predict ε ≈ 40 and one trapped seed predicts ε ≈ 25, mean = 35 (outside the 1 % band) while median = 40 (inside). The median discards the outlier sample-by-sample. Three is the smallest odd ensemble for Complex; Real needs five because all LeakyReLU / ReLU members make correlated errors on the same singular-corner sample, so a wider ensemble is needed before the median can filter them out.

Stage 5 is exposed in the program as an opt-in checkbox on /evaluate and /infer (default off). At deployment the trained ensemble alone hits feasibility on both pipelines; enabling Stage 5 tightens worst-case error by another ≈2× at the cost of a per-sample optimisation pass.

Loss functions

Every loss below receives a pair of tensors ε̂ (prediction) and ε (target). The real MLP outputs a packed [Re, Im] 2-vector; the complex MLP outputs a native complex tensor (paired real / imaginary halves). Per-family loss menus:

  • Real MLP — mse, smooth_l1, eps_rel_mse: shape-agnostic residuals on the packed [Re, Im] tensor.
  • Complex MLP — mse, smooth_l1, or physics_forward: mse / smooth_l1 dispatch through the model-aware loss factory to the complex kernels (complex_mse_loss / complex_smooth_l1_loss); physics_forward is now a hybrid L = base + λ·NRW_residual with the base term being complex_mse_loss and λ sampled from log [1e-3, 1].

EpsRelMse — the variance-crusher loss (shipped default for both pipelines)

MSE on packed [Re, Im] tensors weights every sample by the magnitude of its absolute residual: bulk samples (|ε| ≈ 30) contribute the lion's share of the gradient and the singular corner (|ε| ≈ 1.5) is almost invisible. EpsRelMse divides each squared residual by |ε|² after the target scaler's inverse transform, so a 1 % relative miss contributes the same loss whether the target is 1.5 or 30. Effect at training time (Stage 2 of the stack above): cross-seed standard deviation on the worst sample's relative error collapses from ≈10 pp to ≈0.07 pp — the optimiser literally minimises the reported metric. Both pipelines ship this loss as the default; physics_forward and smooth_l1 stay available in the HPO menu.

REAL MLP — shape-agnostic losses MSE — mean squared error: Real: L = 𝔼[ (ε̂ − ε)² ] ← on packed [Re, Im] Smooth L1 / Huber (β = 1.0): ½·Δ² / β if |Δ| < β L = |Δ| − β/2 otherwise Δ = ε̂ − ε (per component) EpsRelMse — squared relative error, scale-aware (shipped default): L = 𝔼[ |ε̂ − ε|² / |ε|² ] Both sides inverse-transformed through the fitted target scaler so the ratio lives in physical data-space. The dataset enforces ε' ≥ 1, so |ε| ≥ 1 and the denominator never approaches zero — no floor on the divisor is needed.

Physics-forward — the Complex MLP loss

The Complex MLP is tasked with the inverse S → ε problem, but the forward ε → S problem has a closed-form solution: the Nicolson-Ross-Weir (NRW) transfer-matrix formulae for a non-magnetic sample in a rectangular waveguide (see the NRW section above). That gives us a directly differentiable way to ask "does the predicted ε̂ actually produce the measured S-parameters?" — which is exactly what we want the network to optimise for.

Instead of scoring the prediction in ε-space (where MAPE / phase / scale trade-offs had to be hand-designed across multiple iterations), we push the prediction through the forward model and measure the residual in S-parameter space, where the physics already defines the right geometry.

What is NRW_stable?

NRW_stable is the physics kernel — a pure-Rust, fully differentiable implementation of the direct (forward) NRW problem: given a permittivity ε and the waveguide geometry, return the S-parameters a vector network analyser would measure. It is the source of truth for both data generation (the synthetic training set is produced by sweeping ε through this kernel) and the physics-forward loss below (the predicted ε̂ is pushed through the same kernel and compared against the measured S in S-parameter space).

NRW direct problem (the kernel called NRW_stable) Inputs: ε — relative permittivity ε = ε′ − jε″ f — operating frequency a — waveguide width (WR-90 → 22.86 mm) d — sample thickness (default 1.5 mm) 1. Cutoff & propagation constants: λ_c = 2·a (TE10 cutoff wavelength) γ_air = (2π/c)·√( (c/2a)² − f² ) (air, evanescent below cutoff) γ_mut = (2π/c)·√( (c/2a)² − ε·f² ) (sample, ε-dependent) 2. Reflection coefficient at the air ↔ MUT interface: Γ = (γ_air − γ_mut) / (γ_air + γ_mut) 3. Transmission factor through the slab: T = exp( −γ_mut · d ) 4. Two-port S-parameters of the loaded slab: S₁₁ = Γ·(1 − T²) / (1 − Γ²·T²) S₂₁ = T·(1 − Γ²) / (1 − Γ²·T²) Outputs: (S₁₁, S₂₁) ← what the VNA would measure The "stable" suffix refers to the backward gradient: the standard principal-sqrt has a 1/√0 pole at the vacuum boundary (ε ≈ 1 + 0j) that would NaN the physics-loss gradient. NRW_stable rewrites the sqrt for inputs with Re(z) ≥ 0 as (u, v) = ( √((|z|+a)/2), b/(2u) ) which is algebraically equivalent in the forward pass but bounded in backward — always on for the physics-forward path.

The inverse problem (S → ε) the network solves is the hand-pickable inversion of those four steps; the direct problem above is closed-form, single-branch, and trivially differentiable, which is exactly why we use it both to generate training data and to score predictions in S-space:

Physics-forward (hybrid PINN) loss (Ŝ₁₁, Ŝ₂₁) = NRW_stable(ε̂; waveguide, f) ← stable-sqrt path (S₁₁, S₂₁) = NRW_stable(ε; waveguide, f) (always-on default) L_phys = 𝔼[ |Ŝ₁₁ − S₁₁|² + |Ŝ₂₁ − S₂₁|² ] ← complex MSE in S-space L_base = complex_mse(ε̂, ε) ← residual in ε-space L_Total = L_base + λ · L_phys ← hybrid mixing λ ∈ log [1e-3, 1] — sampled per HPO trial, default 1e-3 in /train. waveguide: WR-90 (a = 22.86 mm, d = 1.5 mm) by default f : operating frequency (8.2 GHz by default) Default geometry matches the dataset generator's defaults — so a training run on a default-generated dataset reconstructs exactly the S-parameters the dataset was built from. The NRW backward path uses a stable-sqrt formulation so gradients are bounded at the vacuum boundary (ε ≈ 1 + 0j), where the standard principal-sqrt has a 1/√0 pole that would NaN the physics-loss gradient.

Implementation notes: data generation is deterministic and noise-free, so NRW(ε) reproduces the stored S exactly — NRW(ε̂) − NRW(ε) = Ŝ − S up to FP rounding. The graph is fully differentiable; |S| ≤ 1 by passivity so the loss is self-bounded. Both ε̂ and ε are inverse-transformed through the fitted target scaler before the forward pass. λ is the single mixing scalar (HPO-sampled from log [1e-3, 1]; default 1e-3 in /train).

Data pipeline — generation, scaling, batching

Every trial sees the same three splits (train / val / test) in the same order. The /generate workflow samples ε′/ε″ from the configured range, runs the NRW forward model to produce (S11, S21), and writes one row per sample. The splits are persisted and re-used across every training and HPO run on the same dataset.

INPUT SCALING (StandardScaler on train split) Fit on the training features only, then transform all three splits: μ = mean(train_features) σ = std(train_features) + 1e-12 ← zero-σ guard x_std = (x − μ) / σ Targets use the SAME StandardScaler recipe. EpsRelMse runs `scaler.inverse_transform(·)` before dividing by |target| so the ratio lives in physical data-space; MSE and Smooth L1 operate directly on the scaled tensors because their residual is scale-equivariant.
BATCHING & SHUFFLING batch size ∈ {8, 16, 32, 64, 128, 256, 512, ALL} DataLoader iterates `ceil(n / batch_size)` batches/epoch. Shuffle seed pins the ChaCha8 RNG; HPO pins every trial to the study's base seed so each trial sees the same batch order. `ALL` disables mini-batching — one step per epoch, full-grad. Determinism All randomness (shuffling, init, dropout masks, input noise) flows through a single seeded ChaCha8 stream. Fixed seed ⇒ bit-for-bit reproducible forward & backward pass.

Training loop — warmup, early stopping, LR schedule

Each epoch streams the train split, evaluates on val, then lets the val metric drive both early stopping and the best-weight snapshot that gets restored at end of training.

pseudocode (one epoch): for (x, y) in train_loader: ŷ = model.forward(add_gaussian_noise(x, σ), train=True) grads = loss_fn(ŷ, y).backward() if max_grad_norm: clip_grad_norm_stable(grads, vars, max_grad_norm) optimizer.step(grads) ← weight decay here val_loss = evaluate(model, val_loader) ← no dropout / no noise lr_scheduler.step(epoch, val_loss) best_weights = snapshot if val_loss improved early_stop if (epoch − best_epoch) ≥ patience and epoch ≥ warmup_epochs on exit: model.vars ← best_weights ← restore-best

Warmup blocks early-stopping for the first N epochs so an unlucky initial loss spike can't kill the run. Patience halts training after that many post-warmup epochs without val-loss improvement; the trainer then restores the best-val-loss snapshot, not the last epoch.

LR schedulers

COSINE (default): η(t) = η_min + ½·(η₀ − η_min)·(1 + cos(π · t / T)) PLATEAU: η ← max(η · plateau_factor, plateau_min_lr) on val-loss stall NONE: η ≡ η₀

Optimizers

Four optimizers sampled by HPO; all work on both Real and Complex pipelines. AdamW (default) applies decoupled weight decay and is the production pick. The other three — adam (L2 folded into the gradient), sgd (optional momentum / Nesterov), rmsprop (EMA of squared grads) — stay in the menu so HPO can sample alternatives. sgd and rmsprop open conditional sub-knobs (momentum, Nesterov, α) when picked.

HPO — NSGA-III, Pareto front, fANOVA

Both pipelines (Real and Complex) use the same custom NSGA-III sampler with the same three objectives — there is one HPO loop in the program, not one per family. NSGA-III maintains a population over the search space and selects trials using dominance + reference- point niching after every completed evaluation. (NSGA-II via Optuna appears in the Python ↔ Rust migration benchmark only, as the historical Python baseline; production HPO does not use it.)

OBJECTIVES (vector-valued, evaluated on the perturbed test grid): 1. OK@1% — MAXIMISE fraction of samples with relative error < 1 % 2. param_count — MINIMISE total real-valued learnable parameters 3. max_error — MINIMISE worst-sample relative error (%) Dominance: trial A dominates B iff A ≥ B on every objective AND A > B on at least one. Pareto front = the set of non-dominated trials after the study ends.

A per-trial feasibility flag (✓/✗ in the HPO tables) flags crashed / diverged / NaN trials so dominance only counts trials that actually trained.

Parameter importance — fANOVA vs Spearman

After the study ends, each hyperparameter's variance share per objective is decomposed by fANOVA (default, ≤ 2k trials — random-forest main-effect shares plus a grey "interactions" residual that sums to 100 %) or by Spearman rank correlation (fallback for larger studies — no interactions term, but cheap to compute).

Metrics — what the numbers mean

RELATIVE ERROR (per test sample): r_i = |ε̂_i − ε_i| / |ε_i| (the dataset enforces ε' ≥ 1, so |ε_i| ≥ 1 — no floor on the divisor) OK@τ (top-line metric, τ ∈ {1%, 10%}): OK@τ = (1/N) · |{ i : r_i < τ }| · 100 % MAX ERROR (worst-case relative error): max_error = 100 · max_i r_i MEAN ERROR: mean_error = (100/N) · Σ r_i R² (per real/imag component): R²_re = 1 − Σ(Re(ε̂_i) − Re(ε_i))² / Σ(Re(ε_i) − mean(Re(ε)))² R²_im analogous on the imaginary component.

OK@1 % is the primary metric; max_error is the blow-up catcher (one sample at 300 % can sink a deployment regardless of bulk OK@1); param_count is the deployment knob (smaller networks are cheaper at inference and usually preferred over marginally-better-accuracy ones at the Pareto front). Relative error uses the magnitude of the complex difference, |ε̂ − ε| / |ε|, not per-component.

Reproducibility & determinism

All stochastic ops (init, shuffle, dropout, input noise) draw from a single seeded ChaCha8 stream. Same seed + shuffle_seed ⇒ bit-identical weights across runs (covers forward, backward, dropout, noise, grad clipping). Each HPO trial uses study_seed + trial_number so retraining a trial from the HPO page reproduces its max_error bit- for-bit. Gradient clipping sums squared grad norms in a deterministic parameter order so the global norm is permutation-invariant.
